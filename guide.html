매주 새로운 팀원과 해커톤을 할 때, 손발 맞추는 데 드는 시간을 줄이기 위한 안내서입니다.

① 시작하기 (5분)

  1. github.com/bbbjyc/hackathon-template 에서 "Use this template" 버튼 클릭 → 이번 주 프로젝트용 새 저장소 생성
  2. 그 저장소 Settings → Collaborators에서 오늘 팀원 GitHub 아이디 초대
  3. 각자 컴퓨터에 git clone
개발에 쓰는 AI 도구(Codex, Cursor, Claude Code 중 무엇이든)는 이 저장소를 열면 자동으로 협업 규칙을 읽습니다. 사람이 따로 설명 안 해줘도 됩니다.

② 설계도 채우기 — 코드보다 먼저

집을 지을 때 설계도 없이 벽부터 쌓지 않는 것처럼, 코드를 짜기 전에 팀 전체가 아래 내용을 같이 논의해서 정합니다. 이걸 건너뛰면 나중에 각자 만든 부분이 서로 안 맞아서 다시 만들어야 하는 상황이 생깁니다.

  • 한 줄 목표: 우리 앱이 정확히 뭘 해결하는지
  • 기술 스택: 프론트/백엔드/DB로 뭘 쓸지
  • 기능 간 통신 방식: 화면과 서버가 어떤 데이터를 주고받을지 (표로 정리)
이 부분은 AI에게 맡기지 말고 사람이 직접 정하세요. AI는 "이렇게 하면 되지 않을까"를 추측할 뿐, 팀이 진짜 원하는 방향을 알지 못합니다.

③ 역할 나누기

방식설명추천 여부
기능별 (수직)한 사람이 로그인 기능이면 화면부터 서버까지 통째로 담당✅ 추천 — 서로 기다릴 일이 적음
계층별 (수평)한 사람은 화면만, 한 사람은 서버만△ 팀이 크고 역할이 뚜렷할 때만

역할을 정했으면 누가 뭘 맡았는지 화이트보드나 이슈트래커에 적어서 다 같이 볼 수 있게 해두세요.

④ 개발하면서 지킬 것

깃허브 사용 규칙

  • 작업 시작 전엔 항상 git pull (팀원이 그 사이 뭘 바꿨을 수 있음)
  • 작업 끝날 때마다 커밋 + push (몰아서 하지 말고 자주, 조금씩)
  • 설계도(공유 규칙 문서)를 고쳤다면, 조용히 올리지 말고 팀 단톡방에 한 줄 알리기

AI 도구 쓸 때

  • AI가 만든 코드도 처음에 정한 설계도와 맞는지 사람이 한 번은 눈으로 확인
  • 서로 다른 사람이 각자 AI를 쓰면 같은 문제를 다른 방식으로 풀 수 있음 → 애매하면 설계도에 규칙을 미리 적어두기

⑤ 제출 전 체크리스트

  • 모든 기능이 실제로 서로 연결되어 동작하는지 확인했다
  • 비밀번호/API 키 같은 민감정보가 깃허브에 올라가지 않았다
  • README에 실행 방법을 정리했다
